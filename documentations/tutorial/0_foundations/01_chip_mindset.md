# 认清这颗芯片：STM32 那颗脑子，不是 ST 一个人造的

咱们手里那颗叫「STM32」的芯片，牌子挂的是 ST（意法半导体），可它最核心的那颗大脑，ST 自己造不出来——那是 ARM 公司设计的。牌子归牌子，脑子归脑子，两码事；很多人折腾了大半年 STM32 都没把这层分清，出了问题只能拿关键词去搜索引擎里赌运气。这一章咱们不写一行代码，就把这层关系彻底掰开，把「出了问题该翻哪本书」这件事一并交代清楚。

## ST、ARM，和一个俄罗斯套娃

这串名字的层级规整得像个俄罗斯套娃：ST 是厂商，意法半导体；它家 32 位的 MCU 产品线叫 STM32；再往里一层，F1 是主打性价比的主流系列，内核用的就是 Cortex-M3；F103 是 F1 里被增强过、能跑到 72 MHz 的子系列；最里头那层 C8T6，才是咱们这块板子上焊着的具体型号。

C8T6 这四个字符不是随便编的，它是这块芯片的身份证——`C` 说的是 48 个脚（LQFP48 封装），`8` 说的是 64 KB Flash，`T` 说的是 LQFP 封装，`6` 说的是能在 -40 到 85 ℃ 下干活。这几个数不用背，后面咱们会反复拿它们去和数据手册（datasheet）核对——查出来、对上，才算真的认下了这块板子。

至于「Blue Pill」——它压根不在这串编号里。这不是 ST 的官方型号，是社区里流传最广的一款 STM32 最小系统板的名字：蓝色的小长条，像极了电影里那颗蓝色药丸，名字就在社区里传开了。咱们真正学的是焊在上面的那颗 STM32F103C8T6，Blue Pill 只是它最常见的一块载板。把这层想明白，咱们就不会纠结「我这板子是黑的，怎么也叫 Blue Pill」。

## 发动机和整车：Cortex-M3 不是 STM32

感谢AI，在我绞尽脑汁的思考到底怎么说清楚的时候，他说——**Cortex-M3 是发动机，STM32 是装了发动机的整车。**

Cortex-M3 是 ARM 公司设计的 CPU 内核，单独一颗，它只会取指令、做运算、响应中断，没有 GPIO、没有串口、没有 Flash——一台光秃秃的发动机，装不到车上啥也干不了。ST 干的事，是买下这台发动机的授权，在它外面包上 Flash、SRAM、GPIO、USART、定时器、ADC、时钟电路这一大堆外设，封成一颗拿来就能用的芯片——这台能直接开走的整车，才叫 STM32。

分清这俩为什么要紧？因为**出了问题，咱们该翻的书完全不一样**——后面每章撞了坑，都回到这张表找对的文档，别拿搜索引擎赌：

| 咱们碰上的麻烦                                  | 该翻的文档                                                | 凭啥是它                     |
| ----------------------------------------------- | --------------------------------------------------------- | ---------------------------- |
| 程序跑飞、栈爆了、中断进不去、HardFault         | 《Cortex-M3 权威指南》                                    | 这是**内核**、ARM 定的行为   |

## 它就是一台计算机，只是被塞进了一颗芯片里

很多人下意识觉得单片机是个「玩具」，笔者刚接触那会儿也这么想。其实它就是一台完整的计算机，只不过个头小、被塞进了一颗芯片里：咱们写代码用的「硬盘」是 Flash，64 KB，程序就烧在里头；运行时的变量住在 SRAM 里，20 KB——内存小得可怜，后面写代码得天天惦记它；CPU 是那颗最高跑到 72 MHz 的 Cortex-M3；主板上分发信号的「总线」，在它身上分成 AHB / APB1 / APB2 三条；至于键盘、网卡这些「外设」，对应的正是 GPIO、USART、SPI、I2C。

把这层对应关系立起来，后面每学一个外设，咱们都知道它是这台小计算机里的哪个零件，而不是在背一坨孤立的函数名——USART 就是给这台机器装的一张「嘴和耳朵」，让它跟电脑一个字节一个字节地说话——等串口那一章（P3）把这张嘴和耳朵接通，咱们天天靠它看 `printf` 的输出。

这里笔者埋一个伏笔，留到 P0.3（C 语言硬件基础）兑现——CPU 到底是怎么「控制」这些外设的？答案四个字：**内存映射**。CPU 把每个外设的控制旋钮，都映射成了内存里的某个地址，往那个地址写个数，就等于拧了一下旋钮。这就是为什么咱们后面会看到 `GPIOC->BSRR = ...` 这种代码：它看着是在「写内存」，骨子里是在「驱动硬件」。现在记个结论就行，到时候咱们亲手拆它。

## Blue Pill 的老坑：灯不亮、串口空白、板子没反应

板子的核心参数就一行，后面反复要用：**64 KB Flash / 20 KB SRAM / 72 MHz / 3.3 V 供电（USB 的 5 V 进板子后，被板载稳压器降了下来）/ 板载一颗 PC13 指示灯**。

板载那盏 LED 怎么点都不亮，多半不是板子坏了——这盏灯是**低电平点亮**的（P3 点灯那章咱们正面收拾它）。根子在接法：LED 正极接到 3.3 V，负极经限流电阻接到 PC13，只有 PC13 输出低电平，电流才流得过去、灯才亮。所以照抄网上那些「输出高电平点亮 LED」的代码，灯纹丝不动，还容易冤枉板子坏了。

板上那个 micro-USB 口，接的是芯片的 **USB 外设，不是串口**——插上它、打开串口工具，多半一片空白，新手最容易在这儿怀疑人生：`printf` 的输出根本不会从 USB 口出来。想看串口，得另接一根几块钱的 USB-TTL 模块到 PA9/PA10（也就是 USART1）上，这也是本课程调试阶段离不开 USB-TTL 的原因。

代码明明下进去了，板子愣是没反应——碰上这种事，头一个该查的就是 BOOT0 那个跳线。它决定芯片上电后从哪儿启动：拨到 1，进芯片内置系统存储器里的引导程序（bootloader），走串口或 USB 烧录靠的是这条路；拨回 0，从 Flash 启动，跑咱们自己的程序。咱们课程走 ST-Link 的 SWD 烧录，BOOT0 平时留在 0 就行——经典的「代码下进去了、板子没反应」，多半就是哪回拨去 1 之后忘了拨回来。

还有电平这一条：**STM32 是 3.3 V 逻辑**。引脚里多数标了 FT（5 V 容忍），数字信号直接接 5 V 没事；但 PA0–PA7、PB0/PB1 这批挂着 ADC 的脚不是 FT，直接灌 5 V 进去，轻则读数错乱，重则把脚烧了——FT 也只救数字信号，别指望它扛 5 V 供电。比它更容易漏的是共地：STM32 跟任何外部器件之间**必须共地**，地不接到一块儿，信号再标准也读不到。这条留到 P0.4（电源、共地与逻辑电平）专门讲。
